## Automated checks

Environment: JDK 21 and the existing Gradle/toolchain versions, with the
`pdfeditor_test` Android 15/API 35 arm64 emulator.

```sh
./gradlew :app:ktlintCheck test :app:connectedDebugAndroidTest :app:assembleRelease
```

The full command passed:

- 86 JVM tests in debug and 86 in release: no failures, errors, or skips.
- 26 instrumented tests: no failures, errors, or skips.

The interaction tests cover multipage editing, Open With, exact saved-snapshot
dirty state, source replacement, draft recovery, copying PDF text, remembered
display settings, both layouts, pinch/ink arbitration, and page reordering.
New regressions verify direct inline text without a dialog, grouped text undo,
live drafts, pure-black controls, object selection outlines, the bottom-right
Save menu, and caret visibility while typing long or bottom-of-page notes.

A final visual-only correction made the page overview's append tile and badges
black; ktlint and the release build were repeated, followed by a manual overview
check. No dependencies changed during this final UI pass. The existing R8 Kotlin
metadata and deprecated Compose API warnings remain; they do not fail the build.

## Coverage limits

This is emulator evidence on API 35, not physical-device or API 26 runtime
validation. Existing PDF text and vectors are preserved; this app adds
annotations rather than changing arbitrary existing PDF objects. Foreign
annotations remain preserved but are not editable here, and platform rendering
omits some foreign annotation types. OCR and encrypted PDFs are unsupported.
Common Latin, Greek, and Cyrillic glyphs are supported; complex-script shaping
is unvalidated. SAF providers govern replacement semantics. See the README and
the earlier multipage validation record for further details.
