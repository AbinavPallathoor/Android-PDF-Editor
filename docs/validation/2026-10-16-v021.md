# PDF Editor v0.2.1 validation — 16 October 2026

## Changes

The document header stays visible at the beginning of a PDF, with the page
positioned below its controls. Its compact 64dp control area sits below the status/camera inset. A separate
48dp fade holds black for the first quarter, then fades linearly to transparent. Document swipes follow the finger, spring back
when cancelled, preload adjacent thumbnails, and hold the previous display frame
until the next document renders. Navigation uses the previewed URI and flushes
unsaved drafts. The document panel separates page/view controls from file actions
with equally divided cells and visible boundaries.

- 39 instrumented tests: no failures, errors, or skips.

New regressions cover the header's automatic return at the top, page placement
below its controls, fade continuity, finger-following swipes, cancelled gestures,
failed-open recovery, exact target metadata, display-frame handoff, and real
navigation between two PDFs while retaining an unsaved annotation draft. Existing
multipage annotation, save, Open With, inline typing, layout, selection, and page
operation tests remain in the suite. The existing R8 Kotlin metadata and
deprecated Compose API warnings remain; they do not fail the build.

## Text boxes and typography

Selected text boxes have four corner handles after inline typing finishes.
Dragging rewraps the preserved source text without changing its font size;
width/height use PDF points, remain inside the page, and form one undo step.
Cancelled gestures discard the preview. Text colour and fonts live in the
contextual tray, with brief menu/tray transitions and direct finger tracking.
Typeface-backed inline styles are remembered to keep text layout stable.

Sans (Roboto), Serif (Droid Serif), and Mono (Droid Sans Mono) are bundled with
Apache-2.0 licenses and recorded checksums. SAF imports accept embeddable static
TrueType-outline fonts up to 16 MiB, validate them off the UI thread, and retain
them privately. Custom fonts are fully embedded for exact recovery on reopening;
foreign PDF content remains intact. Missing/corrupt font metadata and bytes can
be restored from matching appearance resources. Draft recovery resolves fonts
without replacing unsaved annotation models. Missing fonts produce an actionable
notice and block reflow until import or explicit font replacement.

Added regressions cover resize/clamping/source preservation, resize undo/redo
and cancellation, selected font/colour changes, actual appearance fill colour,
font embedding, invalid imports, incomplete metadata, exact font recovery in a
fresh library, and dirty-draft font recovery. The resize interaction failed
before handles existed; the missing-font draft regression failed before recovery
was added. Validation also caught and fixed inline font-family identity causing
repeated layout and consumed cancellation releases being treated as commits.

## Coverage limits

This is API 35 emulator evidence, not physical-device or API 26 runtime
validation. Animation checks establish interaction and transition behavior, not
physical-device frame-rate measurements. PDF content and annotations are not
rasterized by the temporary navigation display frame. Other existing PDF
rendering, font, encryption, and SAF limitations remain documented in the
[README](../../README.md#current-limits). No library dependencies changed; bundled-font licenses were added.

The first fresh-emulator run failed
`longPagedNoteKeepsTheCaretVisibleAcrossSuccessiveTypingUpdates` when the
software keyboard was not shown. Caret tracking had incorrectly required a
visible IME. Removing that condition keeps active text visible with either an
on-screen or external keyboard; the original failing regression then passed.
The final full suite was repeated with a simulated display cutout enabled.

After reducing the corner handles, ktlint, JVM tests, the release build and
three resize/style/cancellation UI tests were repeated successfully. A final
visual adjustment keeps handles inside page edges; ktlint, JVM tests and the
release build passed again, followed by signed-APK resize/style/save checks.
