# PDF Editor 0.2.3 validation

## Behavior

Hand in editing mode selects and moves ink strokes, text, and signatures in PDF
coordinates. A stroke keeps its shape and width, stays within page bounds when
it fits, and commits one undo entry on release. Cancellation or a second finger
cancels the object preview. Zoomed Hand navigation handles a single finger in
both layouts; child object/text gestures keep priority. Horizontal pan survives
scrolling across page boundaries. Layout/document changes still reset pan.

The compact header is solid black, including the camera inset. No gradient or
white backdrop remains. Discard all changes in the bottom-right save menu ends
inline editing, restores the saved page/annotation snapshot, clears both history
stacks, persists the reverted draft and removes the save icon.

Only explicit destination save writes PDF bytes. App exit and document switching
persist a private editable draft, leaving the source unchanged. Saved app-owned
annotations remain editable too; saving does not flatten them. A recovered dirty
draft is identified as unsaved.

Temporary external VIEW/SEND handoffs are validated and copied into app-private
imported_documents before their Recents entry is recorded. The URI/content hash
identity reuses the existing imported copy for repeat handoffs; changed source
bytes get a separate copy so the earlier draft survives. Recents retain the
provider/display name and can reopen without the original grant. Existing
persisted SAF and app-owned FileProvider URIs retain their original identity.
Older URI-keyed drafts are carried into a first imported copy with their
immutable base and preferences, retaining the old session and respecting an
existing destination draft. Source fingerprints remain intact for conflict
detection. Saving to the current imported copy affects that copy only; the menu explains
that the file in the sending app remains unchanged.

## Regression evidence

Before fixes, five targeted Compose tests failed on the expected missing
behavior: ink movement, one-finger pan in both layouts, Discard, and solid black
header pixels. The ink bounds JVM regression and temporary intake regressions
also failed before implementation. A further test reproduced a 100px sideways
jump at a scrolling page boundary and passed after preserving horizontal pan.

## Scope

Validation uses an isolated Android 15/API 35 arm64 emulator. The regular
development emulator is untouched. This does not establish physical-device or
API 26 runtime coverage. No OCR, arbitrary Unicode shaping, cryptographic
signatures, or universal foreign-annotation rendering is claimed. No app network
permission, network code, or dependency was added. Release assets contain only
the signed APK, with the checksum in release notes; no screenshots are attached.
