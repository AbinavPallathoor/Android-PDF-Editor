# Reading, saving and rename validation - v0.2.5

## Changes

- **Zoom.** Pages re-render only after a pinch settles (120ms) and keep their
  previous bitmap until the sharper one is ready, so a page never turns white
  mid-zoom. Pages entering view while zooming out start from the best render in
  memory or a 360px neighbour preview. Pinches scale about the finger midpoint,
  zoomed one-finger pans fling, Hand double-tap zooms 1x/2.5x, and pinching past
  0.25x/5x resists and springs back. Past the 2048px whole-page cap, the visible
  part of a page is re-rendered alone at screen resolution, so deep zoom is sharp.
- **Opening.** A fresh import copies and hashes the source in one read, parses it
  once, and uses the imported bytes as the clean base when the PDF has no
  app-owned annotations. Text extraction no longer copies and reparses the PDF
  per page under the render lock. On the API 35 emulator, a generated 300-page
  PDF (debug build) went from 4.7s to about 2.5s to its first page, and the
  import step from 2.6s to 0.4–1.0s.
- **Saving.** Save-as suggests the current name, switches the reader to the new
  file (added to Recents), and shows where it went, e.g. "Internal storage ›
  Download". The original's draft returns to its saved state.
- **Rename.** On Android 11+ with All files access (requested once on first
  launch, and again when renaming without it), rename changes the file itself.
  SAF renaming (`DocumentsContract.renameDocument`) was built first and failed
  live: it renamed the file on both the device-storage and Downloads providers,
  but revoked the app's access to the document. Without the permission, on
  Android 8–10, or for files with no shared-storage path, rename is app-only.
- **Back** from a PDF opened by another app returns to that app.
- **Editing.** The eraser removes every app-made object a swipe crosses, as one
  undo step. Text boxes and signatures have a single bottom-right resize handle.
  Signature line width scales with the signature; older signatures keep their
  look until first resized.
- **Landscape.** The reader, header and tray avoid side insets and cutouts, the
  tray and panel cap at 560dp, page grids adapt their column count, and the
  reading position is kept across rotation.

## Evidence

- ktlint passes. 191 JVM tests pass, including new ones for focal and elastic
  zoom maths, single-parse import inspection, proportional signature export
  width, multi-object erase as one undo step, folder labels, shared-storage
  path mapping, and file rename (including never overwriting an existing file).
- 73 instrumented tests pass on a fresh install (API 35 emulator), including new
  ones for: no blank page during a pinch, zooming about the fingers, sharp
  deep-zoom render of the visible part, spring-back past maximum zoom, swipe
  erase with one undo, a single resize handle, and Back to the calling app (cold
  and warm launch). Existing tests that assumed Back → Home from another app were
  updated to the new behaviour.
- Checked live on the emulator: landscape layout and rotation, save-as with the
  location notice and the original untouched, first-launch All files access
  page, renaming a file in Download, then force-stopping the app, reopening it
  from Recents and saving into the renamed file (21,268 → 23,900 bytes).

## Release build

`assembleRelease` (R8 and resource shrinking): unsigned APK 8,682,776 bytes
(8.28 MiB), below the 15 MiB budget. Package `com.pdfeditor.app`, version 0.2.5,
code 7, minimum API 26, target API 36. Requested permissions:
`MANAGE_EXTERNAL_STORAGE` (new, used only for rename) and the app-local
dynamic-receiver permission. There is still no Internet permission.
